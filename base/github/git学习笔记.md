# 1 Git配置

## 1.1 安装后配置

安装完 Git 之后，要做的第一件事就是设置自己用户名和邮件地址 。因为通过 Git 对项目进行版本管理的时候， Git 需要使用这些基本信息，来记录是谁对项目进行了操作。

```
git config --global user.name "用户名"
git config --global user.email "邮箱"
```

如果使用了 -- global 选项，那么该命令只需要运行一次即可永久生效。

## 1.2 Git 的全局配置文件

`c:/Users/用户名文件夹/.gitconfig`

这个文件是Git的全局配置文件，配置一次即可永久生效

## 1.3 检查配置信息

查看所有的全局配置项

```
git config --list --global
```

查看指定的全局配置项

```
git config user.name
git config user.email
```

# 4 三个区和4种状态

## 4.1 三个区

工作区、暂存区和Git仓库

## 4.2 工作区文件的4种状态

未跟踪、未修改、已修改、已暂存

未跟踪（Untracked）：不被Git所管理的文件

未修改（Unmodified）：工作区中文件内容和暂存区中文件的内容保持一致

已修改（Modified）：工作区中文件的内容和暂存区中文件的内容不一致

已暂存（Staged）：工作区中被修改的文件已被放到暂存区，准备将修改后的文件保存到Git仓库中

Git操作的终极结果：让工作区中的文件都处于”未修改“状态

## 4.3 查看文件状态

```
git status
```

精简方式

```
git status -s
git status --short
```

# 5 Git文件操作

## 5.1 跟踪新文件

文件添加到暂存区，处于暂存状态，精简模式下文件名前显示标记：绿色A

```
git add 文件名
```

## 5.2 提交更新

文件提交到Git仓库，处于"未修改"状态

```
git commit -m "描述消息"
```

## 5.3 已提交的文件进行修改

对于已经被提交的文件，在工作区和Git仓库内容保持一致

当工作区文件被修改后，精简模式下文件会带红色M标记

文件被暂存后，红色M标记会变为绿色M标记

```
git add 文件名
```

文件被提交后，又变为"未修改"状态

## 5.4 向暂存区一次性添加多个文件

```
git add .
```

## 5.5 撤销对文件的修改

对工作区中文件进行修改后，放弃修改，还原称Git仓库中所保存的版本

本质就是用Git仓库中保存的文件，覆盖工作区中指定的文件

```
git checkout --文件名
```

## 5.6 取消暂存的文件

```
git reset HEAD 文件名
```

## 5.7 跳过暂存，直接提交

```
git commit -a -m "描述消息"
```

## 5.8 移除文件

### 5.8.1 同时从工作区和仓库移除

```
git rm -f 文件名
```

### 5.8.2 仅从仓库移除

```
git rm --cached 文件名
```

## 5.9 查看提交历史

```
//查看全部历史
git log
//查看最近的2次历史
git log -2
//在一行上查看最近2次提交历史
git log -2 --pretty-oneline
//自定义输出格式,%h提交的简写哈希值 %an作者 %ar修订日期 %s提交说明
git log -2 --pretty="format：%h| %an | %ar | %s "
```

## 5.10 版本跳转

查看提交历史后，执行以下命令回退

```
git reset --hard <CommitID>
```

回退后，要查看所有提交历史

```
git reflog --pretty=online
```

## 5.11 分支

### 5.11.1 查看分支

列出所有分支，带*的为当前所处分支

```
git branch
```

### 5.11.2 创建分支

创建新的分支是基于当前分支的，新分支的代码和当前分支完全一样

```
//创建新分支，但不切换
git branch 分支名
//创建并切换分支
git checkout -b 分支名
```

### 5.11.3 切换分支

```
git checkout 分支名
```

### 5.11.4 合并分支

先切换到要合并别的分支的主分支上

```
git merge 被合并分支名
```

### 5.11.5 删除分支

确保已经不处于要删除的分支上

```
git branch -d 要删除的分支名
```

### 5.11.6 合并分支时遇到冲突

两个分支中对同一文件进行了不同的修改，合并分支时候，需要打开手动解决冲突，冲突解决后执行下列命令

```
git add .
git commit -m "提交信息"
```

## 5.12 远程分支操作

### 5.12.1 推送本地分支到远程仓库

如果远程仓库分支和本地同名，则远程分支名可省略

```
//第一次推送
git push -u 远程仓库别名 本地分支名：远程分支名
//以后推送
git push
```

### 5.12.2 查看远程分支

```
git remote show 远程仓库名
```

### 5.12.3 下载远程仓库分支

下载远程仓库分支到本地，保持本地分支和远程分支名相同

```
git checkout 远程分支名
```

下载远程仓库分支到本地，重命名本地分支

```
git checkout -b 本地分支名 远程仓库名/远程分支名
```

### 5.12.4 拉取远程分支最新代码

```
git pull
```

### 5.12.5 删除远程分支

```
git push 远程仓库名 --delete 远程分支名
```

# 6 忽略文件

创建一个名为.gitignore的配置文件，在其中列出要忽略的文件的匹配模式

#开头是注释

/结尾是目录

/开头防止递归

！开头表示取反

glob模式：简化了的正则表达式

`*`匹配零个或多个任意字符

`[ ]`匹配任何列在方括号中的字符

`?`匹配单个任意字符

`[开始字符数字 - 结束字符数字]`匹配这两个字符范围内

`**`匹配任意中间目录
