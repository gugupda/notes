# VS Code 集成 Git 详细指南

深入了解 VS Code 与 Git 的集成使用，是开发中高效版本控制的核心技能。下面从基础配置到高级操作，全面拆解 VS Code 集成 Git 的完整流程：

## 一、前置条件：本地 Git 环境准备

VS Code 本身不自带 Git 程序，**必须先在本地安装并配置 Git 环境**，否则 VS Code 无法调用 Git 相关功能：

1. **Git 安装**：从 [Git 官网](https://git-scm.com/downloads) 下载对应系统（Windows/Mac/Linux）的安装包，按默认向导完成安装（Windows 建议勾选 “Git Bash Here” 等便捷选项）。

2. **Git 基础配置**：安装完成后，打开终端（Git Bash / 系统终端），配置全局用户名和邮箱（这是 Git 提交记录的标识，必须配置）：

   ```bash
   # 配置用户名
   git config --global user.name "你的用户名"
   # 配置邮箱（建议与 GitHub/Gitee 等代码托管平台一致）
   git config --global user.email "你的邮箱地址"
   # 验证配置是否生效
   git config --list
   ```

3. **VS Code 关联 Git**：默认情况下，VS Code 会自动检测本地已安装的 Git。若未识别，可手动配置 Git 路径：

   - 打开 VS Code → 快捷键 `Ctrl + ,`（Mac 是 `Cmd + ,`）打开设置
   - 搜索 `git.path`，点击 “编辑 in settings.json”
   - 配置 Git 可执行文件路径（示例）：
     - Windows：`"git.path": "C:\\Program Files\\Git\\bin\\git.exe"`
     - Mac/Linux：`"git.path": "/usr/local/bin/git"`

## 二、核心操作：初始化 Git 仓库（两种场景）

VS Code 集成 Git 的第一步是关联 Git 仓库，分「本地新建仓库」和「克隆远程仓库」两种核心场景：

### 场景 1：本地项目初始化 Git 仓库（无远程仓库时）

适用于本地已存在项目，需要开始版本控制的场景：

1. 打开 VS Code → 菜单栏 `文件` → `打开文件夹`，选择你的本地项目文件夹
2. 打开 VS Code 左侧「源代码管理」面板（快捷键 `Ctrl + Shift + G` / `Cmd + Shift + G`，图标为分支样式）
3. 面板顶部会显示「初始化仓库」按钮，点击后，VS Code 会在当前项目根目录创建 `.git` 隐藏文件夹（仓库核心文件），完成本地仓库初始化
4. 初始化后，项目中所有文件会被标记为「未跟踪状态」（默认红色 / 灰色显示）

### 场景 2：克隆远程 Git 仓库（已有远程仓库时）

适用于从 GitHub/Gitee/GitLab 等平台克隆已有仓库到本地的场景，两种操作方式：

#### 方式 1：VS Code 图形化操作

1. VS Code 欢迎页 → 点击「克隆仓库」；或 菜单栏 `查看` → `命令面板`（`Ctrl + Shift + P` / `Cmd + Shift + P`），输入 `Git: Clone` 并选择
2. 在弹出的输入框中，粘贴远程仓库的 URL（支持 HTTPS 和 SSH 两种格式，推荐 SSH 免密登录）
3. 选择本地保存路径，点击「克隆」，等待 VS Code 完成仓库拉取和加载

#### 方式 2：终端命令操作（更灵活）

1. 打开 VS Code 内置终端（`Ctrl + `` / `Cmd + ``）

2. 执行克隆命令：

   ```bash
   # HTTPS 格式（需输入账号密码/个人访问令牌）
   git clone https://github.com/用户名/仓库名.git
   # SSH 格式（需提前配置 SSH 密钥，免密登录）
   git clone git@github.com:用户名/仓库名.git
   ```

3. 克隆完成后，通过 `文件` → `打开文件夹` 加载克隆后的项目即可

## 三、核心工作流：暂存 → 提交 → 推送

这是 Git 版本控制的核心流程，VS Code 提供了便捷的图形化操作，同时也支持终端命令：

### 1. 暂存更改（Stage Changes）

当你修改、新增或删除项目文件后，Git 会追踪这些更改，**暂存操作是将更改标记为 “待提交” 状态**，相当于 `git add` 命令：

- 图形化操作：

  1. 打开「源代码管理」面板，会看到所有未暂存的更改（分为「已修改」和「未跟踪」）
  2. 单个文件暂存：点击文件右侧的「+」图标（或右键文件选择「暂存更改」）
  3. 全部文件暂存：点击面板顶部的「+」图标（对应 `git add .` 命令，暂存所有更改）
  4. 取消暂存：已暂存的文件可点击右侧「-」图标（对应 `git reset HEAD <文件>` 命令）

- 终端命令：

  ```bash
  # 暂存单个文件
  git add 文件名/文件路径
  # 暂存所有更改
  git add .
  # 取消单个文件暂存
  git reset HEAD 文件名
  ```

### 2. 提交更改（Commit Changes）

暂存完成后，需要将更改提交到本地仓库，**提交时必须填写提交信息，描述本次更改的内容**，相当于 `git commit` 命令：

- 图形化操作：

  1. 在「源代码管理」面板的输入框中，填写清晰的提交信息（如：“修复登录按钮样式问题”）
  2. 点击输入框上方的「√」图标（或快捷键 `Ctrl + Enter` / `Cmd + Enter`）完成提交
  3. 提交失败排查：若提示 “no user configured”，说明本地 Git 未配置用户名 / 邮箱，需返回第一步补配置

- 终端命令：

  ```bash
  # 提交并填写提交信息（推荐，会打开编辑器让你输入详细信息）
  git commit -m "你的提交信息"
  # 若未暂存直接提交（快捷方式，相当于 git add . + git commit）
  git commit -am "你的提交信息"
  ```

### 3. 推送更改（Push Changes）

提交仅将更改保存到本地仓库，**推送操作是将本地提交同步到远程仓库（如 GitHub）**，相当于 `git push` 命令，前提是本地仓库已关联远程仓库：

- 图形化操作：

  1. 若首次推送，面板顶部会提示「推送到 origin」（origin 是远程仓库的默认别名），点击即可
  2. 非首次推送：右键已提交的记录（或面板顶部点击「⋯」→ 选择「推送」）
  3. 推送失败排查：若远程仓库有更新（他人已推送更改），需先拉取远程更新再推送

- 终端命令：

  ```bash
  # 首次推送（关联远程分支并推送，master/main 为分支名）
  git push -u origin main
  # 非首次推送（直接推送当前分支到远程）
  git push
  ```

## 四、分支管理：创建 → 切换 → 合并 → 推送

分支是 Git 实现并行开发的核心（如主分支 `main/master`、开发分支 `dev`、功能分支 `feature/*`），VS Code 提供了直观的分支管理界面：

### 1. 查看 / 切换分支

- 图形化操作：

  1. VS Code 底部状态栏会显示当前所在分支（如 `main`）
  2. 点击状态栏的分支名称，会弹出所有本地和远程分支列表，点击对应分支即可切换（对应 `git checkout` 命令）

- 终端命令：

  ```bash
  # 查看所有分支（本地+远程）
  git branch -a
  # 切换到已有分支
  git checkout 分支名
  # 新版 Git 推荐的切换命令
  git switch 分支名
  ```

### 2. 创建分支

- 图形化操作：

  1. 点击底部状态栏分支名称 → 弹出列表后，输入新分支名称（如 `dev-20251220`），回车即可创建并切换到该分支（对应 `git checkout -b` 命令）
  2. 或在「源代码管理」面板 → 「⋯」→ 「分支」→ 「创建分支」

- 终端命令：

  ```bash
  # 创建并切换到新分支
  git checkout -b 新分支名
  # 仅创建分支（不切换）
  git branch 新分支名
  ```

### 3. 合并分支

常用于功能分支开发完成后，合并到主分支或开发分支（以「将 feature 分支合并到 main 分支」为例）：

- 图形化操作：

  1. 先切换到目标分支（main 分支）
  2. 打开「源代码管理」面板 → 「⋯」→ 「分支」→ 「合并分支」
  3. 在弹出的列表中选择要合并的分支（feature 分支），点击确认即可
  4. 若出现冲突，VS Code 会高亮显示冲突文件，提供「接受当前更改」「接受传入更改」「接受两者更改」「比较更改」四个选项，手动解决冲突后暂存并提交即可

- 终端命令：

  ```bash
  # 切换到目标分支
  git checkout main
  # 合并 feature 分支到 main 分支
  git merge feature分支名
  # 解决冲突后，暂存并提交冲突文件
  git add 冲突文件名
  git commit -m "解决分支合并冲突"
  ```

### 4. 推送分支

新建的本地分支默认未同步到远程仓库，需要手动推送：

- 图形化操作：切换到新建分支后，面板会提示「推送到 origin」，点击即可创建远程对应分支并推送

- 终端命令：

  ```bash
  # 推送本地新分支到远程，并关联远程分支
  git push -u origin 新分支名
  ```

## 五、拉取远程更新（Pull）

当团队成员向远程仓库推送了新的更改，你需要拉取这些更新到本地，保持本地仓库与远程同步，相当于 `git pull` 命令：

- 图形化操作：

  1. 打开「源代码管理」面板 → 「⋯」→ 选择「拉取」
  2. 或直接点击底部状态栏的「同步更改」图标（双向箭头），同时完成「拉取」和「推送」（若本地有未推送的提交）

- 终端命令：

  ```bash
  # 拉取远程当前分支的更新
  git pull
  # 拉取指定远程分支的更新到本地当前分支
  git pull origin 远程分支名
  ```

## 六、其他实用功能

1. **查看提交历史**：
   - 图形化操作：「源代码管理」面板 → 「⋯」→ 「查看提交历史」，可查看所有提交记录、提交人、时间和更改内容
   - 终端命令：`git log`（详细日志）、`git log --oneline`（简洁日志）
2. **撤销更改**：
   - 未暂存的更改：右键文件 → 「放弃更改」（对应 `git checkout -- <文件>` 命令，恢复文件到上一次提交状态）
   - 已提交的更改：可通过「提交历史」右键对应提交 → 「回滚到此次提交」（谨慎使用，会覆盖后续提交）
3. **.gitignore 文件**：
   - 在项目根目录创建 `.gitignore` 文件，填写不需要 Git 追踪的文件 / 文件夹（如 `node_modules/`、`.vscode/`、`dist/` 等）
   - VS Code 会自动识别 `.gitignore`，忽略对应文件的更改追踪

### 总结

VS Code 集成 Git 的核心要点可归纳为 3 点：

1. 前置准备：必须先安装并配置 Git 环境，VS Code 才能正常调用 Git 功能；
2. 核心流程：本地初始化 / 克隆仓库 → 暂存（add）→ 提交（commit）→ 推送（push），分支管理（创建 / 切换 / 合并 / 推送）；
3. 操作方式：支持图形化（源代码管理面板、状态栏）和终端命令两种方式，灵活适配不同开发习惯。

通过以上操作，即可在 VS Code 中高效完成 Git 版本控制的所有核心需求，提升开发协作效率。
