### Script Mode（脚本模式）全解析

这段内容介绍了 NiceGUI 框架的**脚本模式（Script Mode）**，是一种简化的页面开发方式，专为快速原型开发、演示场景设计，核心是摆脱传统的 `@ui.page` 装饰器或根函数（root function）约束，直接在脚本顶层编写 UI 代码即可生成可运行的页面。

#### 1. 核心背景：传统方式的痛点

NiceGUI 常规开发页面有两种主流方式：

- **`@ui.page` 装饰器**：为特定 URL 绑定页面逻辑（如 `@ui.page('/')` 定义根路径页面）；
- **根函数（root function）**：通过 `ui.run(root)` 传入一个函数，函数内定义页面结构（如前文讲解 `ui.sub_pages` 时的示例）。

这两种方式适合正式开发，但在**快速写原型、做演示**时会显得繁琐（需要定义函数 / 装饰器，多一层封装），因此脚本模式应运而生。

#### 2. 脚本模式的核心规则

- **代码位置**：UI 代码直接写在脚本顶层（无需包裹在函数内）；
- **执行逻辑**：每个客户端（浏览器）连接时，顶层代码会**执行一次**，为该客户端独立创建界面（不同客户端的界面相互隔离，互不影响）；
- **运行方式**：只需调用 `ui.run()` 即可启动服务，自动生成可访问的页面。

#### 3. 示例代码解读

```python
from nicegui import ui

# 顶层代码：直接创建 UI 组件，无需函数/装饰器包裹
ui.label('No @ui.page, no root function, but still a working page!')

# 启动服务，自动生成页面
ui.run()
```

运行该脚本后，访问 NiceGUI 默认端口（如 `http://localhost:8080`），会直接显示标签内容，无需额外配置路由或页面函数。

#### 4. 关键注意事项

- **适用场景**：仅适合**简单原型、快速演示、小工具**开发；复杂应用（如多页面、路由跳转、数据共享）仍建议用 `@ui.page` 或 `ui.sub_pages`；
- **客户端隔离**：每个浏览器窗口 / 标签页连接时，顶层代码都会重新执行，组件实例是独立的（比如 A 客户端修改输入框内容，B 客户端看不到）；
- **文档使用习惯**：官方文档中的大部分演示示例都采用脚本模式，目的是**精简代码、聚焦核心功能**（避免函数 / 装饰器的冗余代码干扰对关键 API 的理解）。

#### 5. 脚本模式 vs 传统模式对比

| 特性       | 脚本模式                   | 传统模式（@ui.page/ 根函数）   |
| ---------- | -------------------------- | ------------------------------ |
| 代码结构   | 顶层直接写 UI，极简        | 需包裹在函数 / 装饰器中        |
| 适用场景   | 快速原型、演示             | 正式开发、复杂应用             |
| 多页面支持 | 不支持（仅单页面）         | 支持（多路由 / 嵌套路由）      |
| 客户端隔离 | 自动隔离（每次连接重执行） | 需手动处理（如通过 data 参数） |
| 灵活性     | 低（无路由、参数传递）     | 高（支持路由参数、动态路由）   |

### 总结

脚本模式是 NiceGUI 为「快速验证想法、简化演示代码」设计的便捷模式，通过省略页面函数 / 装饰器的封装，让开发者能以最少的代码编写可运行的 UI 页面。但它仅适用于简单场景，复杂应用仍需回归 `@ui.page` 或 `ui.sub_pages` 等结构化开发方式。
